## 1. Per-agent usage data sources: where each tool records token usage and session data, how open-source trackers collect and price it, and how accurate the cost numbers are

### Takeaway
Every terminal agent (Claude Code, Codex, Gemini CLI, Copilot CLI, OpenCode, Pi, Grok Build, Amp CLI) writes per-session token data to plaintext local files that existing trackers simply tail and price with LiteLLM's price table, so a local "odometer" is technically easy for these tools but rests on internal formats the vendors explicitly call unstable; IDE agents (Cursor, Windsurf/Devin Desktop, Copilot in editors) keep usage server-side and can only be polled through undocumented, cookie/token-reuse endpoints. Dollar figures are estimates at list price (vendors say so themselves) and are notional for subscription users; only Pi stores a computed cost per message, everything else must be computed.

#### Sanctioned real-time interfaces (Claude Code is by far the richest)
- Claude Code pipes a JSON document to a user-configured status-line command; it includes `cost.total_cost_usd`, `cost.total_api_duration_ms`, `context_window.*` (including `current_usage.input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`), `rate_limits.*`, `prompt_cache.*`, `session_id`, `transcript_path`, `model.id`, `version` — [Claude Code status line](https://code.claude.com/docs/en/statusline)
- The status-line script runs when a new assistant message arrives, after `/compact`, on permission-mode changes, and optionally every N seconds via `refreshInterval` (minimum 1); updates are debounced at 300 ms — [Claude Code status line](https://code.claude.com/docs/en/statusline)
- `cost.total_cost_usd` is an "Estimated session cost in USD, computed client-side at list price unless a `modelPricing` table is in effect. May differ from your actual bill. Resets to $0 when `/clear` starts a new session" — [Claude Code status line](https://code.claude.com/docs/en/statusline)
- Claude Code exports OpenTelemetry when `CLAUDE_CODE_ENABLE_TELEMETRY=1`: metrics `claude_code.token.usage`, `claude_code.cost.usage` (default export interval 60 s) and per-request `claude_code.api_request` events carrying `cost_usd`, `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_creation_tokens`, `model`, `query_source` (default logs export interval 5 s) — [Claude Code monitoring](https://code.claude.com/docs/en/monitoring-usage)
- Anthropic describes OTel as working "on every setup" and "the only option that streams per-user token and cost metrics into your own observability stack in near real time" — [Claude Code costs](https://code.claude.com/docs/en/costs)
- Codex can export OTel via `[otel]` in `~/.codex/config.toml` (`exporter = "none"` / `otlp-http` / `otlp-grpc`); events include `codex.api_request` and `codex.sse_event` with "token counts on `response.completed`" — [Codex advanced config](https://learn.chatgpt.com/docs/config-file/config-advanced)
- Gemini CLI has `telemetry.enabled`, `telemetry.target` (`local` or `gcp`), `telemetry.otlpEndpoint`, `telemetry.outfile` settings — [Gemini CLI configuration](https://geminicli.com/docs/reference/configuration)
- Session transcripts are plaintext and include "Complete tool results (file contents, command output, pasted text)"; "If a tool reads `.env` or a command prints a credential, that value is written here" — [.claude directory](https://code.claude.com/docs/en/claude-directory)

#### How existing open-source trackers collect data
- ccusage reads local agent logs only; its README lists Claude Code, Codex, OpenCode, Amp, Droid, Codebuff, Hermes Agent, pi-agent, Goose, OpenClaw, Kilo, Kimi, Qwen, GitHub Copilot CLI, Gemini CLI, Antigravity, Grok Build CLI and ZCode, and prices tokens with LiteLLM pricing data embedded at build time, with per-model overrides in `ccusage.json` — [ccusage README](https://github.com/ryoppippi/ccusage)
- ccusage's Claude Code status line (`ccusage statusline`) combines stdin JSON from Claude Code with transcript files to show session cost, cost today, the current 5-hour block with time left, and a burn rate in $/hr; `--cost-source` can be `auto`, `ccusage`, `cc` or `both` — [ccusage statusline guide](https://ccusage.com/guide/statusline)
- CodexBar (Swift menu bar app, about 69 providers) uses a per-provider fallback ladder: for Claude "OAuth API -> CLI PTY -> Web API", for Codex OAuth API then `codex app-server` RPC then PTY `/status` then web dashboard, plus local JSONL scans for cost history cached in `~/Library/Caches/CodexBar/cost-usage/` — [CodexBar docs/claude.md](https://raw.githubusercontent.com/steipete/CodexBar/main/docs/claude.md); [CodexBar docs/codex.md](https://raw.githubusercontent.com/steipete/CodexBar/main/docs/codex.md); [CodexBar README](https://github.com/steipete/CodexBar)
- tokscale ("Native Rust core") parses local files for 50+ clients; for Cursor it uses "Cursor's web API export" cached as CSV after login with desktop credentials or a pasted `WorkosCursorSessionToken` cookie; pricing lookup is custom overrides, then LiteLLM/OpenRouter — [tokscale README](https://github.com/junhoyeo/tokscale)
- Splitrail (Rust) tracks Gemini CLI/Qwen Code, Claude Code, Codex CLI, Cline/Roo/Kilo, Copilot (VS Code and CLI), OpenCode, Pi and Grok from local data, offers optional upload to "Splitrail Cloud" for "cross-machine usage aggregation", and can run as an MCP server (`splitrail mcp`) — [Splitrail README](https://github.com/Piebald-AI/splitrail)
- Agent Sessions (Swift, macOS 14+) reads 15 agents' session directories (e.g. `~/.codex/sessions`, `~/.claude/projects`, `~/.copilot/session-state`, `~/.pi/agent/sessions`), derives Codex limits from "Codex rollout token_count events", and for Claude uses "paste-a-cookie Claude web usage, no CLI or Full Disk Access needed" — [Agent Sessions README](https://github.com/jazzyalex/agent-sessions)
- cc-switch (Tauri 2) "automatically scans each tool's local session logs and tracks requests, tokens, cache hit rate, and spending by provider and model" and shows "official subscription quotas" on provider cards — [cc-switch README](https://github.com/farion1231/cc-switch)
- opcode (Tauri 2, AGPL) browses `~/.claude/projects/` and offers a usage dashboard for Claude Code — [opcode README](https://github.com/winfunc/opcode)

#### Pricing and accuracy
- Claude Code itself says its `/usage` dollar figure is computed "locally from token counts at list price" and "The figure is an estimate, so for authoritative billing see the Usage page in the Claude Console" — [Claude Code costs](https://code.claude.com/docs/en/costs)
- For subscribers the figure is not a bill: "Claude Max and Pro subscribers have usage included in their subscription, so the session cost figure isn't relevant for billing purposes" — [Claude Code costs](https://code.claude.com/docs/en/costs)
- Client-side estimates have been wrong in specific ways: before v2.1.239 Claude Code did not apply the 1.1x data-residency multiplier, "so the session cost figure was lower than the bill"; organisations on contracted rates need a `modelPricing` managed setting for figures to match — [Claude Code costs](https://code.claude.com/docs/en/costs)
- Cache writes are priced by TTL: Claude Code requests a one-hour cache TTL for the main conversation on subscriptions and five minutes on API keys, the one-hour TTL "bills cache writes at a higher rate", and responses report `ephemeral_1h_input_tokens` versus `ephemeral_5m_input_tokens` — [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching)
- Claude Code's own plan-usage breakdown is local-only: "The figures are approximate and computed from local session history on this machine, so usage from other devices or claude.ai is not included" — [Claude Code costs](https://code.claude.com/docs/en/costs)
- ccusage warns for Codex that "local totals can differ from account-wide Codex usage" and that missing compaction usage records "cannot be recovered" — [ccusage Codex guide](https://ccusage.com/guide/codex/)
- LiteLLM (the price table nearly every tracker uses, `model_prices_and_context_window.json`) attributes discrepancies to token ingestion issues, cost-formula problems and stale pricing data, and says "A delta under ~10% is often explained by boundary effects and rounding" — [LiteLLM cost discrepancy guide](https://docs.litellm.ai/docs/troubleshoot/cost_discrepancy)
- Since 4 April 2026, per a news report quoting Anthropic's Boris Cherny, "Claude subscriptions will no longer cover usage on third-party tools like OpenClaw"; such usage is billed as extra usage or via API key — [Cybersecurity News, 2026-04-04](https://cybersecuritynews.com/claude-ends-openclaw-subscriptions/)

### Inferences
- A zero-configuration odometer is achievable for the CLI agents by watching their session directories (FSEvents/inotify) and applying a price table; this is exactly what ccusage, tokscale, Splitrail, Agent Sessions and cc-switch already do, so the data layer is commodity rather than a moat.
- The maintenance burden is structural: at least eight distinct on-disk formats, two of which changed storage engine or location in 2026 (OpenCode JSON to SQLite; Gemini consumer users moved to Antigravity), and Anthropic explicitly reserves the right to change the Claude Code transcript format in any release. A solo developer inherits a permanent parser-maintenance job (CodexBar has shipped 62 releases, see section 2).
- For Claude Code a more robust design than file parsing is available: install a status-line wrapper, HTTP hooks and/or an OTLP receiver on localhost and consume documented fields. The trade-offs are that the app must modify the user's settings, the status-line slot is single-occupancy (a user already running ccusage's status line would need chaining), and data only flows while a session is active.
- "Cost" needs two modes in the UI: real dollars for API-key/usage-credit traffic and a clearly labelled "API-equivalent" figure for subscription traffic. Token usage only becomes known when each response completes, so a "per-minute burn rate" is a step function derived from completed requests, not a smooth meter.
- Cursor, Windsurf/Devin Desktop and Copilot-in-IDE cannot feed a live odometer at all; the best case is periodic polling of private endpoints with reused cookies/tokens.

### Gaps
- Could not confirm from a primary source whether current Claude Code transcripts still contain a `costUSD` field (ccusage docs imply they sometimes do; Anthropic documents no transcript schema).
- OpenCode storage is inconsistently documented (official troubleshooting page shows JSON storage paths; tokscale and a changelog show SQLite `opencode.db` since v1.2). Token/cost column names in `opencode.db` were not verified.
- Token/cost field names for Copilot CLI (`session-store.db`, `events.jsonl`), Amp threads, Grok Build `updates.jsonl` and Devin Desktop ACP events were not verified in primary sources.
- Cursor's `state.vscdb` full per-OS paths were not verified (only the relative path was quoted).
- The third-party blog's depiction of Codex `token_count` (flat fields) conflicts with the struct definitions in the Codex source (`info.total_token_usage` / `last_token_usage`); the source code is treated as authoritative here.
- No quantitative study comparing ccusage/CodexBar cost totals against vendor invoices was found; accuracy claims are vendor caveats, not measurements.
- Web search quota for the session ran out part-way through; several items were verified by direct fetch of known URLs only.

## 2. Subscription-limit data (5-hour / weekly limits, plan quotas): how existing tools read it, what is sanctioned, what breaks, and what triggers keychain prompts

### Takeaway
Only two channels are vendor-documented: Claude Code's status-line `rate_limits` object (active sessions only, Pro/Max only, and reported missing in some builds) and Codex's `account/rateLimits/read` RPC plus the `rate_limits` snapshots Codex writes into its own rollout files. Everything else (Anthropic's `/api/oauth/usage`, claude.ai cookies, ChatGPT `wham/usage`, Cursor/Copilot/Gemini internal endpoints) is undocumented credential reuse that has repeatedly been rate-limited, changed or shut down, and that sits uneasily with Anthropic's rule that developers "may not collect, store, or intermediate Claude.ai credentials or session tokens."

### Cited Findings
- Sanctioned (Claude): the status-line JSON has `rate_limits.five_hour.used_percentage`, `rate_limits.seven_day.used_percentage` and `resets_at` (Unix seconds); the object "appears only for claude.ai Pro and Max subscribers ... and only after the first API response in the session", and each window "may be independently absent" — [Claude Code status line](https://code.claude.com/docs/en/statusline)
- That field has been unreliable: an issue filed 2026-05-29 (Claude Code v2.1.156, Windows 11, Max plan) reports `rate_limits` absent because it is populated from `anthropic-ratelimit-unified-5h-*` / `-7d-*` response headers that were not returned; it was closed "not planned" — [claudeissues.com #63659](https://claudeissues.com/issue/63659-bug-rate-limits-absent-from-statusline-json-for-claude-max-plan-v2-1-156-windows)
- Undocumented (Claude): CodexBar calls `GET https://api.anthropic.com/api/oauth/usage` with header `anthropic-beta: oauth-2025-04-20` and `Authorization: Bearer <access_token>`; it needs the `user:profile` scope ("CLI tokens with only `user:inference` cannot access usage") and takes credentials from its own cache, then `~/.claude/.credentials.json`, then the macOS Keychain service "Claude Code-credentials" — [CodexBar docs/claude.md](https://raw.githubusercontent.com/steipete/CodexBar/main/docs/claude.md)
- Where the Claude credentials live: on macOS in "the encrypted macOS Keychain" (falling back to `~/.claude/.credentials.json`, mode 0600, when the Keychain rejects the write); on Linux `~/.claude/.credentials.json`; on Windows `%USERPROFILE%\.claude\.credentials.json` — [Claude Code authentication](https://code.claude.com/docs/en/authentication)
- The long-lived token from `claude setup-token` "can only make model requests" — [Claude Code authentication](https://code.claude.com/docs/en/authentication)
- The OAuth usage endpoint is hostile to polling: an issue opened 2026-03-06 reports that after requests at 30 to 60 second intervals it returns 429 that "persists indefinitely" with no `Retry-After`, affecting "any tool that displays live Claude usage"; it was closed "not planned" on 2026-06-01 — [claudeissues.com #31637](https://claudeissues.com/issue/31637-bug-api-oauth-usage-endpoint-aggressively-rate-limits-making-usage-monitoring-un)
- Claude Code's own `/usage` hits the same limit: "When the request for your plan limits fails, most often because the usage endpoint is rate limited, `/usage` shows the last usage bars it loaded on this machine within the past 60 minutes" — [Claude Code costs](https://code.claude.com/docs/en/costs)
- Cookie route (Claude): CodexBar imports the `sessionKey` cookie for `claude.ai` from Safari (`~/Library/Cookies/Cookies.binarycookies`), Chrome or Firefox and calls `https://claude.ai/api/organizations/{orgId}/usage` and `/overage_spend_limit`; failure modes include "Cloudflare challenges on `claude.ai`" — [CodexBar docs/claude.md](https://raw.githubusercontent.com/steipete/CodexBar/main/docs/claude.md)
- PTY route (Claude): CodexBar starts `claude` in a pseudo-terminal with `--allowed-tools ""`, sends `/usage`, strips ANSI and parses "Current session" / "Current week" percentages — [CodexBar docs/claude.md](https://raw.githubusercontent.com/steipete/CodexBar/main/docs/claude.md)
- Codex, documented: `codex app-server` exposes `account/read`, `account/rateLimits/read` (`primary` and optional `secondary` with `usedPercent`, `windowDurationMins`, `resetsAt`) and an `account/rateLimits/updated` notification — [Codex app-server](https://learn.chatgpt.com/docs/app-server.md)
- Codex, passive: every `token_count` event may embed a `RateLimitSnapshot` (`primary`, `secondary`, `credits`, `plan_type`, `rate_limit_reached_type`) — [openai/codex protocol.rs](https://raw.githubusercontent.com/openai/codex/main/codex-rs/protocol/src/protocol.rs)
- Codex, undocumented: CodexBar's primary path reads tokens from `~/.codex/auth.json` and calls `GET https://chatgpt.com/backend-api/wham/usage`; fallback is `codex -s read-only -a never app-server` — [CodexBar docs/codex.md](https://raw.githubusercontent.com/steipete/CodexBar/main/docs/codex.md)
- OpenAI tells users to "treat `~/.codex/auth.json` like a password: it contains access tokens"; storage can be `file`, `keyring`, `auto` or `ephemeral` (`cli_auth_credentials_store`) — [Codex authentication](https://learn.chatgpt.com/docs/auth)
- Gemini: CodexBar reads `~/.gemini/oauth_creds.json`, refreshes with a client id/secret "extracted from the installed Gemini CLI", and calls `v1internal:retrieveUserQuota`; "Individual, AI Pro, and Ultra accounts lost OAuth support on 2026-06-18" — [CodexBar docs/gemini.md](https://raw.githubusercontent.com/steipete/CodexBar/main/docs/gemini.md)
- Cursor: tiered credential resolution "Cursor.app local auth -> cached cookie -> browser import -> stored session", then `GET https://cursor.com/api/usage-summary`; cost fetches returning HTTP 403 "trigger six-hour cooldowns" — [CodexBar docs/cursor.md](https://raw.githubusercontent.com/steipete/CodexBar/main/docs/cursor.md)
- Copilot: `GET https://api.github.com/copilot_internal/user` with headers such as `Editor-Version: vscode/1.96.2` and `User-Agent: GitHubCopilotChat/0.26.7`; "Reset dates are not provided by the API" — [CodexBar docs/copilot.md](https://raw.githubusercontent.com/steipete/CodexBar/main/docs/copilot.md)
- Keychain prompts: CodexBar's keychain doc attributes prompts to changed code signatures (accessibility attributes "do not make an unstable or changed code signature satisfy the item's access-control list") and to reading foreign-owned items (Claude Code's, Chrome's); its fix is a no-UI default ("Background work should fail closed, user-initiated work may acknowledge deliberate interactive access") and "explicit, default-off consent" for foreign items — [CodexBar docs/KEYCHAIN_FIX.md](https://raw.githubusercontent.com/steipete/CodexBar/main/docs/KEYCHAIN_FIX.md)
- CodexBar exposes a user-facing keychain prompt policy for Claude OAuth: "Never prompt", "Only on user action" (default), "Always allow prompts" — [CodexBar docs/claude.md](https://raw.githubusercontent.com/steipete/CodexBar/main/docs/claude.md)
- macOS permissions CodexBar asks for: Full Disk Access (optional, for Safari cookies/local storage), Keychain access (browser cookie decryption and credential retrieval), Files and Folders — [CodexBar README](https://github.com/steipete/CodexBar)
- What breaks, empirically: CodexBar's changelog lists 62 versions (latest release 0.56.7 on 2026-09-06) with recurring fixes for keychain prompts, Claude usage endpoint changes, Codex app-server incompatibilities (e.g. 0.54.0 "Fixed Codex CLI 0.149.0 compatibility: the usage probe works again after the CLI removed the `untrusted` approval"), Cursor token decoding, and the Gemini consumer shutdown (0.55.0) — [CodexBar CHANGELOG](https://raw.githubusercontent.com/steipete/CodexBar/main/CHANGELOG.md)
- Terms (current text): "Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens"; OAuth authentication "is designed to support ordinary use of Claude Code and other native Anthropic applications"; "Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice" — [Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- Terms (history): enforcement blocks began 2026-01-09 and the documentation was clarified on 2026-02-19 with the sentence "Using OAuth tokens obtained through Claude Free, Pro, or Max accounts in any other product, tool, or service, including the Agent SDK, is not permitted" — [WinBuzzer, 2026-02-19](https://winbuzzer.com/2026/02/19/anthropic-bans-claude-subscription-oauth-in-third-party-apps-xcxwbn/)

### Inferences
- A commercial app that reads the Claude OAuth token out of the Keychain to call `/api/oauth/usage` is doing something the free tools do, but for a paid product it is the single largest platform risk: it is undocumented, rate-limited to the point of uselessness for live display, closed "not planned" when users complained, and arguably within the "collect, store, or intermediate ... credentials or session tokens" prohibition. None of the sources say read-only usage polling is permitted or forbidden; that is an unresolved legal grey area.
- The lowest-risk design for Claude limits is to consume only the status-line `rate_limits` object (the user's own Claude Code process hands the numbers over), accept that it is blank when no session is running, and extrapolate between samples using `resets_at`.
- For Codex the lowest-risk design is to parse `rate_limits` from the newest rollout file (no credentials touched) and optionally spawn `codex app-server` for `account/rateLimits/read`.
- On a default macOS install Claude credentials are in the Keychain, not a file, so any OAuth-based approach triggers at least one "wants to use your confidential information" prompt, and re-prompts are likely whenever the app's signature changes; this is a first-run trust and support burden.
- Cursor, Copilot and Gemini quotas depend entirely on impersonating first-party clients (cookies, editor user-agent strings, extracted OAuth client secrets). These work today but are the features most likely to break without notice.

### Gaps
- No Anthropic statement was found that explicitly addresses third-party, read-only use of `/api/oauth/usage`.
- Could not retrieve the related issues on `rate_limits` missing in v2.1.141 or on status-line scripts exhausting the OAuth usage rate limit (fetch errors); only titles were seen in search results.
- The exact macOS Keychain ACL mechanics (which API calls prompt, behaviour of "Always Allow" across updates) were not verified in Apple documentation.
- Windows (Credential Manager) and Linux (libsecret) equivalents for these credential stores were not researched beyond the file paths above.
- The version in which `rate_limits` was first added to the status-line JSON could not be confirmed.

## 3. Provider-level spend: which official usage/cost APIs exist, who can use them, how fresh they are, and whether a live per-minute odometer can be built from them

### Takeaway
Official usage/cost APIs exist for Anthropic, OpenAI, OpenRouter, xAI and Cursor, but they are organisation/admin-key products with minutes-to-hours latency (Anthropic about 5 minutes, Cursor hourly, Claude Code Analytics up to 1 hour, Google up to 24 hours for cost graphs) and Anthropic's is explicitly "unavailable for individual accounts". They are suitable for daily reconciliation, not a live odometer; live numbers can only come from local logs, the status line/OTel, or a proxy.

### Cited Findings
- Anthropic Usage and Cost Admin API: `/v1/organizations/usage_report/messages` (buckets `1m`, `1h`, `1d`; group by `model`, `workspace`, `api_key_id`, `service_tier`, etc.) and `/v1/organizations/cost_report` (daily only); requires an Admin API key (`sk-ant-admin01-...`), "workspace API keys don't work" — [Anthropic Usage and Cost API](https://platform.claude.com/docs/en/build-with-claude/usage-cost-api)
- "The Admin API is unavailable for individual accounts." — [Anthropic Usage and Cost API](https://platform.claude.com/docs/en/build-with-claude/usage-cost-api)
- Freshness and polling: "Usage and cost data typically appears within 5 minutes of API request completion, though delays may occasionally be longer"; "The API supports polling once per minute for sustained use"; Priority Tier costs "are not included in the cost endpoint" — [Anthropic Usage and Cost API](https://platform.claude.com/docs/en/build-with-claude/usage-cost-api)
- Only organisation members with the admin role can create Admin API keys; the same key family authenticates the Analytics, Compliance, Spend Limits, Usage and Cost and Rate Limits APIs — [Anthropic Admin API keys](https://platform.claude.com/docs/en/manage-claude/admin-api-keys)
- Claude Code Analytics API (`/v1/organizations/usage_report/claude_code`): daily, per-user records with `model_breakdown` tokens (`input`, `output`, `cache_read`, `cache_creation`) and `estimated_cost`; "Metrics are available with up to 1-hour delay"; covers only Claude API usage (not Bedrock, Foundry, Google Cloud); has a `customer_type` of `api` or `subscription`; Enterprise claude.ai users are reported by a separate Enterprise Analytics API — [Claude Code Analytics API](https://platform.claude.com/docs/en/build-with-claude/claude-code-analytics-api)
- For Teams/Enterprise seats, "Usage inside the seat allowance isn't metered in dollars"; the org spend report is "updated daily" — [Claude Code costs](https://code.claude.com/docs/en/costs)
- OpenAI: `https://api.openai.com/v1/organization/usage/completions` (`bucket_width` `1m`, `1h`, `1d`; group by project, user, API key, model; returns `input_tokens`, `output_tokens`, `input_cached_tokens`, `num_model_requests`) and `https://api.openai.com/v1/organization/costs` where "'1d' is currently only supported"; both need an Admin key — [OpenAI cookbook: Usage API and Cost API](https://developers.openai.com/cookbook/examples/completions_usage_api)
- OpenRouter: `GET /api/v1/key` with an ordinary API key returns `usage`, `usage_daily`, `usage_weekly`, `usage_monthly`, `limit`, `limit_remaining`, `is_free_tier` — [OpenRouter limits](https://openrouter.ai/docs/api-reference/limits)
- OpenRouter management-key endpoints: `GET /api/v1/activity` ("daily usage and spend grouped by model endpoint"), `POST /api/v1/analytics/query`, `GET /api/v1/analytics/meta` — [OpenRouter activity](https://openrouter.ai/docs/guides/features/activity.md)
- OpenRouter `GET /api/v1/credits` "Returns the total credits purchased and used" — [OpenRouter credits](https://openrouter.ai/docs/api-reference/credits/get-credits)
- xAI: a Management API at `https://management-api.x.ai` using a distinct management key covers API-key management, billing (prepaid credit balances and usage deductions) and audit logs — [xAI Management API](https://docs.x.ai/docs/management-api)
- Google Gemini API: usage is monitored in "Google AI Studio in Dashboard > Usage" and Cloud Billing reports; cost graphs "can take up to 24 hours to update" and AI Studio billing data can lag "up to around 10 minutes"; monthly spend caps exist per billing account tier and project; the billing page mentions no programmatic usage API — [Gemini API billing](https://ai.google.dev/gemini-api/docs/billing)
- Cursor Admin API (team/enterprise admins, Basic auth with a team API key): `POST /teams/daily-usage-data`, `POST /teams/spend`, `POST /teams/filtered-usage-events` (with `inputTokens`, `outputTokens`, `cacheWriteTokens`, `cacheReadTokens`, `totalCents`, `chargedCents`); "Data is aggregated at the hourly level — we recommend polling this endpoint at most once per hour"; 20 requests per minute per team — [Cursor Admin API](https://cursor.com/docs/account/teams/admin-api)
- CodexBar's stance mirrors this split: it uses "Admin API spend dashboards (OpenAI, Claude)" when configured and local scans otherwise — [CodexBar README](https://github.com/steipete/CodexBar)

### Inferences
- "Unified daily spend across providers" can be billing-grade only for users who hold organisation admin keys; for the stated target (individual developers), Anthropic spend must be estimated from local logs, Google has no API, and subscription usage has no dollar value at all. The honest product claim is "estimated spend, reconciled against provider APIs where the user supplies an admin/management key".
- Asking users to paste Admin/Management keys into a third-party desktop app is a significant trust ask: those keys can manage members, workspaces and API keys, not just read usage.
- A per-minute odometer cannot be built from provider APIs (minimum 1 to 5 minute lag at Anthropic, daily cost buckets at Anthropic and OpenAI, hourly at Cursor); it must come from local logs, status line/OTel pushes, or an in-path proxy.
- OpenRouter is the one provider where an individual's ordinary key yields near-live daily/weekly/monthly spend, so it is the easiest "official" integration.

### Gaps
- Whether personal (single-user) OpenAI organisations can create Admin keys, and the freshness of OpenAI usage buckets, could not be verified (the reference page fetched lists only the endpoints).
- Specific xAI billing endpoint paths and freshness were not shown on the overview page.
- Freshness of OpenRouter's `usage_daily` counters is not documented on the pages fetched.
- Google Cloud Billing export (BigQuery) and Cloud Monitoring as programmatic routes were not researched.

## 4. Traffic interception: base-URL proxies, TLS interception, Network Extension; which agents can be intercepted; terms and breakage

### Takeaway
Pointing an agent at a local proxy via its base-URL setting is documented and works for Claude Code, Codex (API/custom-provider mode), Copilot CLI in BYOK mode, Aider and other BYOK agents, and Anthropic's docs even describe subscription (OAuth) traffic passing through a gateway if the `anthropic-beta` header is forwarded. But it degrades Claude Code (MCP tool search is unavailable or disabled by default behind a custom base URL, so tool changes invalidate the prompt cache; fine-grained tool streaming is off by default; strict header pass-through is required on every release), does nothing for Cursor (requests originate from Cursor's cloud), and puts a third-party product in the request path that Anthropic's terms treat with suspicion. TLS MITM and macOS Network Extensions are technically possible but poor fits.

### Cited Findings
- Claude Code gateway mechanics: `ANTHROPIC_BASE_URL` selects the Anthropic Messages format (`/v1/messages`, optional `/v1/messages/count_tokens`); a gateway must forward `anthropic-beta` and `anthropic-version` unchanged, must stream (including SSE pings), and must return upstream errors unmodified — [Gateway protocol reference](https://code.claude.com/docs/en/llm-gateway-protocol); [Roll out an LLM gateway](https://code.claude.com/docs/en/llm-gateway-rollout)
- Subscription traffic through a proxy is described by Anthropic: "Setting only that variable, without a gateway credential, doesn't replace the subscription. Requests still route through the gateway, but a saved claude.ai login remains the active credential, so its usage limits and billing apply. Gateways that pass this traffic on to Anthropic must forward the OAuth capability in `anthropic-beta`" — [Other LLM gateways](https://code.claude.com/docs/en/llm-gateway)
- If the header is stripped, such requests fail with 401; the docs tell operators not to allowlist beta values "because the set changes with Claude Code releases" — [Gateway protocol reference](https://code.claude.com/docs/en/llm-gateway-protocol)
- Useful attribution headers a proxy can read without parsing bodies: `x-claude-code-session-id`, `x-claude-code-agent-id`, `x-claude-code-parent-agent-id` — [Gateway protocol reference](https://code.claude.com/docs/en/llm-gateway-protocol)
- Costs of being in the path: "Claude Code adds capabilities with each release, and a gateway that doesn't forward them breaks the corresponding features, so the gateway product needs to be kept updated as Claude Code evolves"; "Anthropic doesn't endorse, maintain, or audit third-party gateway products" — [Other LLM gateways](https://code.claude.com/docs/en/llm-gateway)
- Claude Code's caching doc lists "a custom `ANTHROPIC_BASE_URL` gateway" among the cases where "tool search is unavailable or disabled"; in those cases MCP tool definitions load into the prompt prefix and adding or deliberately removing them invalidates the prompt cache — [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching)
- Fine-grained tool streaming "is off by default whenever requests route through a custom base URL"; the fast-mode availability check "calls `api.anthropic.com` directly rather than following `ANTHROPIC_BASE_URL`"; a gateway that drops `cache_control` markers makes "your entire conversation history" bill as uncached input — [Gateway protocol reference](https://code.claude.com/docs/en/llm-gateway-protocol); [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching)
- Env-var credentials and base URL "apply to the CLI and the surfaces that wrap it, including the VS Code extension, the Agent SDK, and GitHub Actions. Claude Desktop and cloud sessions do not call `apiKeyHelper` or read these environment variables" — [Claude Code authentication](https://code.claude.com/docs/en/authentication)
- TLS interception is technically supported by Claude Code: it honours `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY` ("does not support SOCKS proxies"), trusts the OS certificate store by default (`CLAUDE_CODE_CERT_STORE=bundled,system`) and `NODE_EXTRA_CA_CERTS`; "Enterprise TLS-inspection proxies work without additional configuration when their root certificate is installed in the OS trust store" — [Claude Code network configuration](https://code.claude.com/docs/en/network-config)
- Codex: `openai_base_url` and `[model_providers.<id>]` (`base_url`, `env_key`, `wire_api`) redirect API traffic; Codex ignores `openai_base_url` and `chatgpt_base_url` in project-local config — [Codex advanced config](https://learn.chatgpt.com/docs/config-file/config-advanced); [Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference)
- Copilot CLI BYOK: `COPILOT_PROVIDER_BASE_URL`, `COPILOT_PROVIDER_TYPE` (`openai`, `azure`, `anthropic`), `COPILOT_PROVIDER_API_KEY`, `COPILOT_MODEL`; in that mode requests go directly to the configured provider — [Copilot CLI BYOK](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-byok-models)
- Aider has `--openai-api-base` — [Aider options](https://aider.chat/docs/config/options.html)
- Cursor cannot be meaningfully intercepted locally: "Cursor processes chat and agent context on its own remote servers (`api2.cursor.sh`)", and with a custom base URL "the request path is: Cursor UI -> Cursor's cloud backend -> Override OpenAI Base URL -> LLM Provider", so `localhost` resolves on Cursor's servers; the workaround is a public tunnel — [dev.to: localhost base URL in Cursor](https://dev.to/orchidfiles/why-localhost-doesnt-work-as-openai-base-url-in-cursor-and-how-to-fix-it-589e)
- Existing local proxies: claude-code-router (about 37.3k GitHub stars) runs a local gateway on `http://127.0.0.1:3456` with an observability dashboard showing "resolved providers, latency, token usage, and cost estimates"; cc-switch runs an optional proxy on `http://127.0.0.1:15721` and rewrites tool configs to "the local address and the placeholder key `PROXY_MANAGED`" — [claude-code-router README](https://github.com/musistudio/claude-code-router); [cc-switch README](https://github.com/farion1231/cc-switch)
- Anthropic's note on LiteLLM as a spend-tracking gateway: "This project is unaffiliated with Anthropic and has not been audited for security." — [Claude Code costs](https://code.claude.com/docs/en/costs)
- macOS Network Extension content filters (`NEFilterDataProvider`) examine network flows and allow/block them, require the `com.apple.developer.networking.networkextension` entitlement, and deployment is governed by TN3134; the documentation describes flow examination, not decrypted TLS payloads — [Apple: Content filter providers](https://developer.apple.com/documentation/networkextension/content-filter-providers)
- Terms: developers may not "route requests through Free, Pro, or Max plan credentials on behalf of their users"; the same page says nothing "prevent[s] an end user from signing in to the unmodified Claude Code binary with their own Claude subscription" — [Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)

### Inferences
- A transparent local pass-through proxy for the user's own Claude Code traffic is technically documented behaviour, but shipping it in a paid product makes that product an unendorsed gateway that must track every Claude Code release, will silently raise users' costs when it breaks caching or tool search, and is exposed to the same enforcement discretion that hit third-party harnesses in January to April 2026. The pitch's "intercepting API traffic" should be treated as an optional, off-by-default advanced mode, not the core data path.
- Interception adds little that local logs/OTel do not already provide for Claude Code and Codex (both already expose per-request token counts); its unique value is hard enforcement (rejecting requests) and coverage of agents with no logs. That narrow benefit is unlikely to justify the breakage and trust cost for a solo developer.
- TLS MITM with a custom root CA would work for Claude Code but means installing a trusted root on a developer machine and decrypting traffic that contains source code and credentials: a severe trust and liability problem. A Network Extension cannot read token counts without that same MITM, needs a special entitlement and user approval, and so offers nothing over a base-URL proxy.
- For Codex signed in with ChatGPT, Cursor, Windsurf/Devin Desktop and default Copilot, interception is either impossible or would mean proxying vendor-backend protocols; treat these as non-interceptable.

### Gaps
- Whether Gemini CLI, OpenCode and Pi support a base-URL override (and the variable names) was not verified in primary docs.
- No vendor statement was found on whether running a local pass-through proxy in front of subscription traffic is acceptable for a third-party commercial tool; only the general credential rules exist.
- How Codex traffic behaves through a proxy when authenticated with ChatGPT (as opposed to an API key) was not verified.
- Apple TN3134 (system extension packaging, user approval, distribution limits) was referenced but not read.

## 5. Live session detection and control: enumerating sessions and state, "kill session", and what "clear cached system context" could mean

### Takeaway
Session listing is partly sanctioned (Claude Code `claude agents --json` for background sessions; hooks and OTel for interactive ones; Codex `app-server` only for threads it hosts; OpenCode's HTTP server) and otherwise relies on process inspection and file modification times. Killing is trivially a signal or `claude stop`, with real risk to in-flight tool calls and background work. "Clear cached system context" has no controllable technical referent: the prompt cache is server-side and TTL-driven, and neither `/clear` nor `/compact` can be injected into a running session from outside.

### Cited Findings
- Claude Code background sessions: "`claude agents --json` is the supported way to read session state from outside Claude Code, for example from a status bar, a scheduler"; poll `claude agents --json --all` and read `state` (`working`, `blocked`, `done`, `failed`, `stopped`), `status` (`busy`, `waiting`, `idle`) and `waitingFor`; the JSON also carries `pid`, `sessionId`, `cwd`, `name` — [Claude Code agent view](https://code.claude.com/docs/en/agent-view)
- Limits of that interface: "Interactive sessions you have open in other terminals don't appear until you background them", and subagents/teammates "aren't listed as separate rows"; no token or cost fields are documented in the JSON — [Claude Code agent view](https://code.claude.com/docs/en/agent-view)
- Internal state is off-limits: "The files under `~/.claude/jobs/<id>/` are not a stable interface." — [Claude Code agent view](https://code.claude.com/docs/en/agent-view)
- `~/.claude/sessions/` holds "Running session lock files", removed when a session exits (crash leftovers cleared on next launch) — [.claude directory](https://code.claude.com/docs/en/claude-directory)
- Control commands: `claude stop <id>` ("Also accepts `claude kill`"), `claude respawn <id>`, `claude rm <id>`, `claude daemon stop --any` (stops the supervisor and its sessions; `--keep-workers` leaves them running), `claude logs <id>`, `claude attach <id>` — [Claude Code CLI reference](https://code.claude.com/docs/en/cli-reference)
- Hooks give live lifecycle events for all session types: `SessionStart`, `SessionEnd`, `Stop`, `Notification`, `SubagentStart`/`SubagentStop`, `PreCompact`/`PostCompact`, each with `session_id`, `transcript_path`, `cwd`; hooks can be `type: "http"` posting to a URL — [Claude Code hooks](https://code.claude.com/docs/en/hooks)
- Sending input from outside: `claude -p --resume <session-id> --output-format json "..."` sends a follow-up to an existing (not running) session; for a running background session a prompt passed with `--resume` is delivered as its next turn, but "A prompt that starts with `/` or `!` isn't sent" — [Claude Code sessions](https://code.claude.com/docs/en/sessions)
- What is lost when a process ends: on resume, "A tool that was still running when the previous process ended ... doesn't finish or run again"; "Background Bash and monitor tasks aren't" restored; unfinished background subagents and workflows show up only as a note that they did not finish — [Claude Code sessions](https://code.claude.com/docs/en/sessions)
- Conversations themselves survive: "Sessions are saved continuously to local transcript files as you work" — [Claude Code sessions](https://code.claude.com/docs/en/sessions)
- Codex: `codex app-server` offers `thread/list`, `thread/read`, `thread/loaded/list`, `turn/interrupt`, `thread/archive` and `thread/tokenUsage/updated` notifications, but a third-party client cannot attach to an already-running TUI session; it sees persisted threads and threads it starts or resumes itself — [Codex app-server](https://learn.chatgpt.com/docs/app-server.md)
- Codex `notify` runs an external program with a JSON payload (`type: agent-turn-complete`, `thread-id`, `turn-id`, `cwd`, `input-messages`, `last-assistant-message`); Codex hooks include `SessionStart`, `SessionEnd`, `Stop`, `Interrupt`, `PreToolUse`, `PostToolUse`, `UserPromptSubmit` with `session_id`, `transcript_path`, `cwd`, `model` — [Codex advanced config](https://learn.chatgpt.com/docs/config-file/config-advanced); [Codex hooks](https://learn.chatgpt.com/docs/hooks)
- OpenCode: `GET /session/status` and `POST /session/:id/abort` on its HTTP server (default `127.0.0.1:4096` for `opencode serve`; protect with `OPENCODE_SERVER_PASSWORD`) — [OpenCode server](https://opencode.ai/docs/server/)
- Copilot CLI writes per-process logs named `process-{timestamp}-{pid}.log` and IDE lock files under `~/.copilot/ide/` — [Copilot CLI config dir reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference)
- Ollama: `GET /api/ps` lists running models and a request with `keep_alive: 0` unloads a model — [Ollama API /api/ps](https://docs.ollama.com/api/ps)
- Prompt cache facts: "Caching happens server-side"; entries "expire after a period of inactivity" (five-minute or one-hour TTL); `/clear` starts a fresh context ("`/clear` costs nothing"), while `/compact` "is itself a large request"; the only switch is `DISABLE_PROMPT_CACHING=1`, which turns caching off — [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching); [Claude Code costs](https://code.claude.com/docs/en/costs)
- Mid-session edits to instruction files do not apply: CLAUDE.md files "are read once at session start and held in memory ... The new content loads on the next `/clear`, `/compact`, or restart" — [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching)
- Local data deletion is a documented command: `claude project purge [path]` deletes transcripts, task lists, debug logs, file-edit history and prompt history for a project — [Claude Code CLI reference](https://code.claude.com/docs/en/cli-reference)
- CodexBar's own subprocess handling escalates "from SIGTERM to SIGKILL" on CLI timeouts — [CodexBar docs/codex.md](https://raw.githubusercontent.com/steipete/CodexBar/main/docs/codex.md)

### Inferences
- A practical session list has three tiers: (a) sanctioned and rich for Claude Code background sessions; (b) self-reported via hooks the app installs (Claude Code, Codex, Cursor, Copilot CLI), which is reliable only after the user lets the app edit hook configs; (c) heuristic process scanning (`ps` for `claude`, `codex`, `gemini`, `opencode`, `pi`, `aider`) joined to recently modified session files. Tier (c) is cheap to build and fragile (wrappers, tmux, containers, WSL, renamed binaries).
- "Kill" is easy to implement and easy to regret: SIGINT/SIGTERM to an interactive agent mid-turn abandons the running tool call and background shells and can orphan child processes (dev servers, test runners, MCP stdio servers) unless the whole process group is signalled. Product copy should say "stop", prefer vendor commands (`claude stop`, Codex `turn/interrupt` for hosted threads, OpenCode `/abort`), and confirm before acting.
- "Clear cached system context with one click" should be dropped or redefined. The realistic mappings are: stop the session and start a new one; delete local transcripts (`claude project purge`); or unload a local model (Ollama `keep_alive: 0`). None of these "clears a cache" in the provider sense, and the provider cache cannot be flushed by a client.
- An external tool cannot trigger `/clear` or `/compact` in a live Claude Code session except by driving the terminal (tmux `send-keys` or a PTY), which is brittle and unsafe.

### Gaps
- What `claude stop` does to child processes, worktrees and uncommitted changes is not documented on the pages read.
- Whether `claude agents --json` ever returns `kind: "interactive"` entries (the field is described as `interactive` or `background`) versus the statement that interactive sessions do not appear is unresolved.
- No vendor documentation was found on orphaned-subprocess behaviour after SIGTERM/SIGKILL for any agent; the risk statement above is an inference.
- How to discover the port of an OpenCode TUI's embedded server from outside was not verified.
- Gemini CLI, Pi and Aider lifecycle hooks/lock files were not researched.

## 6. Enforcing budgets: can an external tool actually stop spend, or only alert?

### Takeaway
Hard stops are possible only where the tool controls an enforcement point: vendor hooks that can deny actions (Claude Code, Codex, Cursor), a proxy/gateway that rejects requests, a headless-run budget flag, or killing the process. All client-side mechanisms are cooperative (the developer can remove them), work on estimated spend, and do not exist for Cursor's or Copilot's hosted inference, where the tool can only alert; authoritative caps live with the vendors (workspace spend limits, gateway spend limits, OpenRouter guardrails).

### Cited Findings
- Claude Code hooks that can block: `PreToolUse` (via `permissionDecision: "deny"` or exit code 2), `UserPromptSubmit` (blocks the prompt before it reaches Claude), `PostToolBatch` ("Stops agentic loop before next model call"), `SubagentStop`, `PreCompact`, `ConfigChange`; hooks may be HTTP hooks returning the same JSON — [Claude Code hooks](https://code.claude.com/docs/en/hooks)
- Claude Code's built-in cap is headless only: `--max-budget-usd` is the "Maximum dollar amount to spend on API calls before stopping (print mode only)"; subagent spend counts, and at the cap "spawning another subagent fails with `Budget limit reached`" — [Claude Code CLI reference](https://code.claude.com/docs/en/cli-reference)
- Codex hooks can block with exit code 2 or `"decision": "block"` / `"permissionDecision": "deny"` — [Codex hooks](https://learn.chatgpt.com/docs/hooks)
- Cursor hooks can return `allow`, `deny` or `ask`, and exit code 2 blocks; user-level hooks do not load for cloud agents — [Cursor hooks](https://cursor.com/docs/agent/hooks)
- Copilot CLI has a `preToolUse` hook, but the page read does not document a deny decision — [Copilot CLI hooks](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-hooks)
- Gateway enforcement (vendor-built): Claude apps gateway spend limits return `429` with `error.type: billing_error` once a per-user/group/org daily, weekly or monthly cap is passed; amounts "are USD estimates, a circuit breaker rather than an invoice"; client aborts are billed a floor estimate "so aborting requests early doesn't evade a cap"; enforcement "fails open by default" if its Postgres store is unreachable — [Claude apps gateway spend limits](https://code.claude.com/docs/en/claude-apps-gateway-spend-limits)
- Anthropic also has a public Admin "Spend Limits API" and workspace spend limits in the Console; on subscriptions, admins set usage-credit spend limits "at the organization, group, or individual member level" — [Anthropic Admin API keys](https://platform.claude.com/docs/en/manage-claude/admin-api-keys); [Claude Code costs](https://code.claude.com/docs/en/costs)
- OpenRouter guardrails: "Spending cap in USD that resets daily, weekly, or monthly. Requests are rejected when the limit is reached" (HTTP 403), per member or per API key; "Only organization admins can create and manage guardrails" — [OpenRouter guardrails](https://openrouter.ai/docs/guides/features/guardrails.md)
- Cursor: `POST /teams/user-spend-limit` sets per-user limits (Enterprise only) — [Cursor Admin API](https://cursor.com/docs/account/teams/admin-api)
- Subscription plans stop themselves: seat allowances reset "on a rolling five-hour window and a weekly window", and Claude Code warns at 75% and 95% of a gateway cap — [Claude Code costs](https://code.claude.com/docs/en/costs); [Claude apps gateway spend limits](https://code.claude.com/docs/en/claude-apps-gateway-spend-limits)

### Inferences
- The most defensible local enforcement design is: the app keeps a running estimate and exposes `http://127.0.0.1:<port>/budget`; an installed HTTP hook on `UserPromptSubmit` and `PreToolUse`/`PostToolBatch` denies when the budget is exhausted. This blocks new prompts and the next step of an agent loop, not a response already streaming, and the estimate inherits all the accuracy caveats of section 1.
- Because hooks and proxies are configured in user-writable files, enforcement is a self-discipline feature for individuals and a weak control for teams; an organisation that needs real caps will use vendor-side limits (workspace limits, Spend Limits API, gateway caps, OpenRouter guardrails) that a desktop utility cannot match.
- For subscription users the meaningful "budget" is the plan quota, which the vendor already enforces; the value an external tool can add is early warning (burn-rate projection to the 5-hour or weekly reset), not enforcement.
- Killing a process is the only universal stop, and it is the bluntest one (see section 5).

### Gaps
- Whether Copilot CLI `preToolUse` hooks can deny, and whether Gemini CLI/OpenCode have blocking hooks or plugins, was not verified.
- No evidence was found on how reliably hook-based budget blocks work in practice (e.g. race conditions with parallel subagents); this is untested design.
- The exact semantics of Anthropic's public Spend Limits API (scopes, availability by plan) were not read.

## 7. MCP switchboard: config locations and formats per client, live toggling, risks of rewriting configs, and how existing managers work

### Takeaway
There is no common MCP config: eight clients use five different file formats and key names, most apply file edits only after a restart, and Claude Code's own docs say an edited MCP config "takes effect only after a restart". "Instant" toggling exists only through agent-native commands (Claude Code `/mcp`, Copilot CLI `/mcp disable`, Codex `config/mcpServer/reload`) or by fronting servers with one aggregating proxy that emits `list_changed`, which is how MCP Router and Docker's MCP Gateway work; config-rewriting managers (MCPM, cc-switch, ToolHive's client registration) exist and are mature, and one of them has well over 100k GitHub stars.

#### Live updates and caching
- The MCP spec lets servers declare `tools.listChanged` and send `notifications/tools/list_changed`; the client then re-requests `tools/list` — [MCP specification 2025-11-25: tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)
- Claude Code: when a `list_changed` notification arrives in an interactive session it "fetches the updated list from that server, so you don't need to reconnect it" — [Claude Code MCP](https://code.claude.com/docs/en/mcp)
- Claude Code: "Editing your MCP config does not by itself change the cache. The new config takes effect only after a restart, which is when the server connects or disconnects." — [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching)
- Cache cost of toggling: with deferred tools (tool search, the default on supported models) a server connecting, disconnecting or changing its tool list "only appends new content"; where tools load into the prefix, adding a definition or deliberately removing one (for example "disabling its server in `/mcp`") invalidates the prompt cache — [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching)
- MCP tool definitions "are deferred by default, so only tool names and server instructions enter context until Claude uses a specific tool" — [Claude Code costs](https://code.claude.com/docs/en/costs)

#### Risks in the files themselves
- `~/.claude.json` is shared, hot state: it holds "App state and UI preferences", "OAuth session data", "Per-project trust decisions" and both MCP scopes, and "Claude Code writes to this file when you change settings in `/config` or approve trust prompts"; Claude Code keeps the 5 newest backups in `~/.claude/backups/` — [.claude directory](https://code.claude.com/docs/en/claude-directory)
- Secrets live in or near these files: `.mcp.json` supports env expansion and blanks `ANTHROPIC_API_KEY`-style variables in remote URLs/headers "to prevent credential leakage"; Copilot CLI keeps `mcp-oauth-config/` and `mcp-secrets/` directories; Windsurf/Devin supports `${file:...}` indirection — [Claude Code MCP](https://code.claude.com/docs/en/mcp); [Copilot CLI config dir reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference); [Devin Desktop Cascade MCP](https://docs.devin.ai/desktop/cascade/mcp)
- Project-scoped servers need per-user approval in Claude Code, and enterprise allow/deny lists and `managed-mcp.json` can override anything a local tool writes — [Claude Code MCP](https://code.claude.com/docs/en/mcp)
- Claude Code fires a `ConfigChange` hook "When a configuration file changes during a session", and that hook can block the change — [Claude Code hooks](https://code.claude.com/docs/en/hooks)

#### How existing managers do it
- MCP Router (desktop app, Windows and macOS, about 2.1k stars, "Sustainable Use License"): single aggregating endpoint; clients connect with `npx -y @mcp_router/cli connect`; per-server and per-tool toggles, projects/workspaces, request logging; data stays local — [MCP Router README](https://github.com/mcp-router/mcp-router)
- MCPM: global server registry with profiles; rewrites client config files (`mcpm client edit CLIENT_NAME`, `mcpm client import`) for Claude Desktop, Cursor, Windsurf, VS Code, Cline, Continue, Goose, 5ire, Roo Code, OpenCode; can also run a profile as one server (`mcpm profile run PROFILE --http`) — [MCPM README](https://github.com/pathintegral-institute/mcpm.sh)
- ToolHive: runs servers in containers behind local HTTP/SSE proxy URLs (e.g. `http://localhost:19046/mcp`) and "automatically updates the global MCP configuration file" of registered clients (Claude Code `~/.claude.json`, Cursor `~/.cursor/mcp.json`, Copilot CLI `~/.copilot/mcp-config.json`, VS Code `mcp.json`, plus 13 more); a vMCP aggregator exists — [ToolHive client compatibility](https://docs.stacklok.com/toolhive/reference/client-compatibility); [ToolHive docs](https://docs.stacklok.com/toolhive/)
- Docker MCP Gateway: "centralized proxy between clients and servers, managing configuration, credentials, and access control", launching servers as containers on demand, with profiles selecting the available servers — [Docker MCP Gateway](https://docs.docker.com/ai/mcp-catalog-and-toolkit/mcp-gateway/)
- cc-switch (Tauri 2, MIT, 139k+ stars as displayed on its repo page): "unified MCP panel" choosing "which tools to sync each one to" by rewriting each tool's live config (`~/.claude.json`, `~/.codex/config.toml`, `~/.gemini/settings.json`, ...), with "atomic writes" and first-write backups in `backups/live-first-write/` — [cc-switch README](https://github.com/farion1231/cc-switch)
- Vendors are absorbing this: VS Code auto-discovers other apps' MCP configs, and Claude Code ships `claude import [source]` to "bring configuration from other coding agents into Claude Code" (v2.1.213+) — [VS Code MCP servers](https://code.visualstudio.com/docs/copilot/customization/mcp-servers); [Claude Code CLI reference](https://code.claude.com/docs/en/cli-reference)

### Inferences
- The pitch line "dynamically updating the context available to Claude Code or Cursor instantly" is not achievable by rewriting config files: Claude Code applies file edits at restart, and Cursor's reload behaviour is undocumented. It is achievable for Claude Code only if the app itself is the (single) MCP server the agent connects to and it emits `list_changed` when the user flips a switch.
- The aggregating-proxy design gives instant toggles and one integration point per client, but makes the app a long-running, security-critical process that brokers every tool call (and its credentials), must proxy stdio and HTTP servers plus OAuth flows, and collides with the product's own proxy feature: behind a custom `ANTHROPIC_BASE_URL` tool search is unavailable or disabled by default, so each toggle forces a full prompt-cache rebuild, which costs money (whether tool search can be re-enabled behind a local proxy was not verified).
- The config-rewriting design is simpler but needs per-client adapters for five formats (`mcpServers` JSON, VS Code `servers` JSON, Codex TOML, OpenCode `mcp` with array commands, Gemini settings), careful concurrent-write handling for `~/.claude.json` (which Claude Code rewrites itself), secret handling, and honest UI ("applies at next session start"). Where a vendor CLI exists (`claude mcp`, `codex mcp`, `copilot mcp`) it is the safer write path than editing files.
- This feature area is already crowded with free, mature tools (cc-switch, MCP Router, MCPM, ToolHive, Docker) and with first-party convergence (VS Code discovery, `claude import`), so it is hard to defend as a paid differentiator.

### Gaps
- Whether Cursor, Codex, Gemini CLI, Copilot CLI and OpenCode act on `list_changed` from a connected server mid-session was not verified.
- Cursor's behaviour when `mcp.json` changes on disk (auto-reload vs restart) is not documented on the page read.
- The older Windsurf path `~/.codeium/windsurf/mcp_config.json` (given as a lead) was not confirmed; current docs show `~/.config/devin/mcp_config.json`. Config for the newer "Devin Local" agent was not read.
- No documented incident data was found on config corruption caused by third-party managers; the concurrent-write risk is inferred from the documented fact that Claude Code itself writes `~/.claude.json` and keeps backups.
- MCP Router's implementation stack (Electron or otherwise) was not confirmed.

## 8. Skills injection: where skills/rules/instructions live per agent and whether a common Agent Skills format is shared

### Takeaway
A common format exists and is widely adopted: Agent Skills (`SKILL.md` folder with `name` and `description` frontmatter), originated by Anthropic and now read by Claude Code, Codex, Cursor, Gemini CLI, Copilot, VS Code, OpenCode, Amp, Pi and dozens more, with `~/.agents/skills` and `.agents/skills` as the de facto cross-agent directories (Claude Code being the notable exception, using `~/.claude/skills`). "Skill template injection" is therefore file copying or symlinking: easy to build, already done by cc-switch, and not defensible on its own.

### Cited Findings
- The standard: "a skill is a folder containing a `SKILL.md` file" with metadata (`name` and `description`, at minimum) plus optional `scripts/`, `references/`, `assets/`; "The Agent Skills format was originally developed by Anthropic, released as an open standard, and has been adopted by a growing number of agent products" — [agentskills.io](https://agentskills.io/home)
- Adopters listed on the standard's site include Claude Code, Claude, ChatGPT and Codex, Cursor, Gemini CLI, GitHub Copilot, VS Code, OpenCode, Amp, Goose, pi, Roo Code, Kiro, Factory, Junie, OpenHands, Letta, TRAE, Mistral Vibe, Hermes Agent and OpenClaw — [agentskills.io](https://agentskills.io/home)

| Agent | Skill locations | Notes | Source |

### Inferences
- A cross-agent skill installer reduces to: keep a library, write each skill into `~/.agents/skills/<name>/` and symlink it into `~/.claude/skills/<name>/` (plus project-level equivalents). Claude Code picks it up live; other agents on next discovery or `/skills reload`.
- Portability requires sticking to the standard frontmatter (`name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools`); Claude-only fields make a template silently less useful elsewhere.
- Because vendors and free tools already cover this, skill injection is a table-stakes convenience and a possible content play (curated templates), not a technical moat. Installing third-party skills is also a supply-chain risk (skills can bundle scripts and inject shell commands), so a marketplace would need review and provenance.

- GitHub's Copilot CLI skills page does not itself state adherence to the Agent Skills standard (the standard's site lists GitHub Copilot as an adopter).
- No security guidance specific to third-party skill distribution was researched.

## 9. Stack and distribution: Swift vs Tauri vs Electron, cross-platform reach, App Store sandbox, and trust

### Takeaway
The category's precedents are clear: the Mac-only menu bar trackers are native Swift apps on macOS 14+ distributed outside the Mac App Store with Sparkle and Homebrew, and the cross-platform managers are Tauri 2 apps with Rust cores; none of the tools examined uses the Mac App Store, whose sandbox blocks reading dotfiles and other apps' data without user-granted access and whose reviewers typically reject the exception entitlements that would allow it. An app that reads OAuth tokens, API keys and full transcripts will be judged on trust, where the incumbents already promise local-only processing and no telemetry, mostly as open source.

### Cited Findings
- Swift precedent: CodexBar is Swift/SwiftUI, requires "macOS 14+ (Sonoma)", ships via GitHub Releases and `brew install --cask codexbar`, updates with Sparkle, and offers CLI tarballs for macOS/Linux and an AUR package — [CodexBar README](https://github.com/steipete/CodexBar)
- Swift precedent: Agent Sessions is Swift, macOS 14+, distributed as DMG, Homebrew tap and Sparkle auto-updates, and states "No telemetry, analytics, remote logging, advertising identifiers, or session-history uploads" — [Agent Sessions README](https://github.com/jazzyalex/agent-sessions)
- SwiftUI's `MenuBarExtra` scene is available on macOS 13.0+; menu-bar-only apps set `LSUIElement`; a `.window` style supports richer popovers — [Apple: MenuBarExtra](https://developer.apple.com/documentation/swiftui/menubarextra)
- Tauri precedent: cc-switch is "Tauri 2 · Rust · React 18 · TypeScript · SQLite", runs on Windows 10+, macOS 12+ and Linux (x86_64/ARM64), ships MSI/portable, Homebrew/DMG and DEB/RPM/AppImage, and its repo page displays 139k+ stars — [cc-switch README](https://github.com/farion1231/cc-switch)
- Tauri precedent: opcode is "Rust with Tauri 2" plus React, targets Windows 10/11, macOS 11+ and Linux, is AGPL-licensed, with about 22.4k stars — [opcode README](https://github.com/winfunc/opcode)
- Rust CLI/TUI precedent: tokscale ("Native Rust core") and Splitrail (Rust) are cross-platform terminal tools — [tokscale README](https://github.com/junhoyeo/tokscale); [Splitrail README](https://github.com/Piebald-AI/splitrail)
- Footprint (secondary source, 2026 blog comparison): Tauri bundles 2 to 10 MB versus Electron 80 to 200 MB; idle memory about 30 to 50 MB versus about 120 to 400 MB; Tauri uses the platform WebView (WebView2, WKWebView, WebKitGTK), and "WebKitGTK on Linux has known performance quirks"; Electron's auto-update and signing tooling is "the most mature available" — [DevToolPicks: Tauri vs Electron 2026](https://devtoolpicks.com/blog/tauri-vs-electron-indie-hackers-2026)
- Tauri 2 tray support exists (`tray-icon` feature, `TrayIconBuilder`), but on Linux tray icon events are unsupported (menus only) — [Tauri: system tray](https://v2.tauri.app/learn/system-tray/)
- App Sandbox: a sandboxed app has full access only to its own container in `~/Library/Containers`; other files come through user-chosen open/save panels and security-scoped bookmarks, or folder entitlements for standard locations; "If your app tries to access the sandbox container owned by another app, the system asks the person using your app whether to grant access" — [Apple: Accessing files from the macOS App Sandbox](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox)
- Dot-folder access needs `com.apple.security.temporary-exception.files.home-relative-path.*`, and an Apple engineer on the developer forums says of App Review: "my experience is that they typically reject folks using temporary exception entitlements", while they are fine for apps not shipped via the Mac App Store — [Apple Developer Forums thread 709333](https://developer.apple.com/forums/thread/709333)
- Windows and WSL are first-class Claude Code environments with their own paths (`%USERPROFILE%\.claude\.credentials.json`; WSL reads Windows managed settings only when `wslInheritsWindowsSettings` is true) — [Claude Code authentication](https://code.claude.com/docs/en/authentication); [Roll out an LLM gateway](https://code.claude.com/docs/en/llm-gateway-rollout)
- Sensitivity of what the app would read: transcripts contain file contents and any printed credentials in plaintext ("Only OS file permissions protect these files"); `~/.codex/auth.json` "contains access tokens"; OpenCode's `auth.json` holds "API keys, OAuth tokens" — [.claude directory](https://code.claude.com/docs/en/claude-directory); [Codex authentication](https://learn.chatgpt.com/docs/auth); [OpenCode troubleshooting](https://opencode.ai/docs/troubleshooting/)
- Incumbents' trust posture: CodexBar "Privacy-first. Reuses existing provider sessions ... so no passwords are stored"; MCP Router keeps "Request logs, configurations, and server data" on device; cc-switch is MIT-licensed — [CodexBar README](https://github.com/steipete/CodexBar); [MCP Router README](https://github.com/mcp-router/mcp-router); [cc-switch README](https://github.com/farion1231/cc-switch)
- Resource discipline is a recurring maintenance theme for always-on trackers: CodexBar's changelog repeatedly addresses "Unbounded cache growth, sustained background scanning, process churn" and caps its Codex SQLite cost store — [CodexBar CHANGELOG](https://raw.githubusercontent.com/steipete/CodexBar/main/CHANGELOG.md); [CodexBar README](https://github.com/steipete/CodexBar)

### Inferences
- Recommendation (evidence-based): build the parsing/pricing/watching engine as a Rust core (the proven language for this in tokscale, Splitrail, cc-switch, opcode), usable as a CLI/daemon, and put a thin shell on top: Tauri 2 if Windows/Linux/WSL users are in scope from day one, or a native Swift menu bar shell if the first release is Mac-only and footprint and Keychain behaviour matter most. Electron's idle memory is a poor match for an always-on utility whose pitch is efficiency, and no examined tracker chose it.
- Mac App Store distribution is effectively incompatible with the product: it must read `~/.claude`, `~/.codex`, `~/.gemini`, other apps' Application Support data and Keychain items, spawn vendor CLIs (`claude agents --json`, `codex app-server`), and possibly run a local proxy. Direct distribution (Developer ID signing, notarisation, Sparkle or Tauri's updater, Homebrew cask) is the path every comparable tool takes.
- Cross-platform reach multiplies the adapter matrix: per-OS paths, three credential stores, WSL's separate filesystem, and Linux tray limitations. For a solo developer, "macOS first, engine portable" is the lower-risk sequencing.
- Trust is a go-to-market constraint, not a nice-to-have: users are asked to let a closed-source paid app read tokens, keys and source-code-bearing transcripts while free open-source alternatives promise local-only handling. A credible posture is an open-source (or source-available) core, local-only processing by default, no telemetry, minimal and explicit Keychain access, and never transmitting transcripts.

### Gaps
- No primary benchmark of menu bar/tray app memory for Swift vs Tauri vs Electron was found; the figures are from one 2026 blog post and are generic.
- Whether any AI-usage tracker is distributed through the Mac App Store today was not established (none of the tools examined is).
- Tauri specifics for menu-bar-only behaviour on macOS (activation policy, menu bar title text) and notarisation/updater details were not verified.
- No engineering blog post by a tool maker (e.g. CodexBar's author) was retrieved; the "what broke" evidence is from changelogs and issue trackers.
- Licences of CodexBar, tokscale, Splitrail and Agent Sessions were not checked.

## 10. Multi-machine sync and team features: what is needed, and the security implications of "centralized API key deployment"

### Takeaway
Sync and team features move the product from a local utility to a hosted service handling secrets and source-derived data: they need accounts, a backend, end-to-end encryption and (for teams) an enforcement point that a desktop app does not have. Vendors already ship the team controls natively (per-user spend limits, analytics APIs, managed settings, gateway credentials), and their guidance on key distribution is the opposite of pushing shared provider keys to laptops.

### Cited Findings
- Existing sync approaches: Splitrail offers opt-in upload to "Splitrail Cloud for safe-keeping and cross-machine usage aggregation" (`auto_upload`); cc-switch syncs via user-supplied storage, "WebDAV (Jianguoyun, Nextcloud, Synology NAS, etc.) or S3-compatible storage" — [Splitrail README](https://github.com/Piebald-AI/splitrail); [cc-switch README](https://github.com/farion1231/cc-switch)
- Vendors sync some of this already: VS Code Settings Sync has an "MCP Servers" option; Claude Code loads skills "enabled for your account" from claude.ai in terminal sessions signed in with that account — [VS Code MCP servers](https://code.visualstudio.com/docs/copilot/customization/mcp-servers); [Claude Code skills](https://code.claude.com/docs/en/skills)
- Per-machine blind spot that sync would address: Claude Code's usage breakdown covers "local session history on this machine, so usage from other devices or claude.ai is not included" — [Claude Code costs](https://code.claude.com/docs/en/costs)
- Vendor-native team spend controls: Teams/Enterprise spend limits "at the organization, group, or individual member level" and a spend report with CSV export; Console workspace spend limits; Claude Code Analytics API and Enterprise Analytics API for per-user numbers — [Claude Code costs](https://code.claude.com/docs/en/costs)
- Vendor-native shared limits with real enforcement: Claude apps gateway caps by `user`, `rbac_group` or `organization`, daily/weekly/monthly, enforced on every request against Postgres, with an audit trail — [Claude apps gateway spend limits](https://code.claude.com/docs/en/claude-apps-gateway-spend-limits)
- Anthropic's model for distributing credentials: a gateway where "the provider key stays server-side; developers hold gateway credentials instead"; "Issuing one key per developer rather than a shared key is what makes per-developer usage attribution and individual offboarding work"; distribution via managed settings (`env` block, `apiKeyHelper` that "authenticates to your secrets store as the local developer") pushed by MDM or configuration management — [Other LLM gateways](https://code.claude.com/docs/en/llm-gateway); [Roll out an LLM gateway](https://code.claude.com/docs/en/llm-gateway-rollout)
- Terms boundary: organisations may provision "their own API keys ... in a development environment, secrets manager, or machine image for use by the customer's own authorized users", provided usage "is not resold or intermediated"; for products embedding Claude Code, "Customers may not pay for, resell, or intermediate Claude usage on their end users' behalf" — [Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- OpenRouter offers the same at the provider level: per-member and per-API-key budgets enforced by guardrails, plus (per its docs index) management API keys to "Manage API keys programmatically" and workspace budgets to "Set spending limits per workspace with automatic enforcement" — [OpenRouter guardrails](https://openrouter.ai/docs/guides/features/guardrails.md); [OpenRouter docs index](https://openrouter.ai/docs/llms.txt)
- Cursor Enterprise exposes per-user spend limits via its Admin API — [Cursor Admin API](https://cursor.com/docs/account/teams/admin-api)
- Codex has admin-enforced settings such as `forced_login_method` and `forced_chatgpt_workspace_id` — [Codex authentication](https://learn.chatgpt.com/docs/auth)

### Inferences
- Multi-machine sync needs: user accounts and device enrolment; a backend store; client-side (end-to-end) encryption with keys that never leave devices, because the synced objects include MCP configs with embedded tokens, skill folders with scripts, and usage records that reveal project names and paths; conflict resolution across per-OS path differences; and an explicit exclusion of transcripts. A lighter alternative that avoids running a backend is "bring your own storage" (iCloud Drive, a git repo, WebDAV/S3 as cc-switch does).
- "Shared spend limits" computed from locally estimated usage and enforced by local hooks are advisory: any developer can remove the hook or bypass the proxy, the numbers are estimates, and IDE agents are not covered. Real shared limits require owning the request path (a hosted or self-hosted gateway), at which point the product competes with Anthropic's gateway, OpenRouter, LiteLLM and Cursor's admin controls.
- "Centralized API key deployment" is the highest-risk feature in the plan: it would make the vendor (a solo developer) custodian or distributor of customers' provider keys; a compromise of the sync service or the app's update channel becomes a multi-tenant key leak; pushing a shared provider key to laptops contradicts vendor guidance (per-developer credentials, keys kept server-side, short-lived tokens via helper scripts); and enterprise buyers will ask for SSO, audit logs, SOC 2-style assurances and revocation workflows. A safer scope is "deploy configuration, not secrets": distribute base URLs, settings templates and references to the customer's own secret manager.
- Team features also change the legal posture toward vendors: aggregating or brokering credentials across users is closer to the "intermediate" behaviour Anthropic's terms restrict than a single-user local tool is.

### Gaps
- No public post-mortems or security analyses of Splitrail Cloud, cc-switch sync or similar services were found.
- Regulatory/compliance requirements for a small vendor holding customers' API keys (e.g. SOC 2 expectations, breach notification) were not researched.
- Whether OpenAI/Google terms restrict third-party distribution of API keys was not checked.
- Demand evidence for team features in this category is outside this note's scope.

## 11. Feature-by-feature feasibility assessment (synthesis of the objective)

### Takeaway
The read-only core (local odometer, burn-rate alerts, session list, skill installation) is easy to build today for terminal agents but is commodity and format-fragile; quota gauges and unified provider spend depend on undocumented or admin-only channels; "instant" MCP switching and budget enforcement require the app to sit in the request or tool path; "clear cached system context" is not technically meaningful; and team key deployment is feasible only by becoming a hosted secrets/gateway product, which is out of proportion for a solo developer.

### Cited Findings
- The foundation is unstable by vendor statement: Claude Code's transcript "entry format is internal to Claude Code and changes between versions, so scripts that parse these files directly can break on any release" — [Claude Code sessions](https://code.claude.com/docs/en/sessions)
- A sanctioned alternative exists for Claude Code: status-line JSON (cost, context, rate limits), hooks (including HTTP hooks) and OpenTelemetry events every 5 seconds — [Claude Code status line](https://code.claude.com/docs/en/statusline); [Claude Code hooks](https://code.claude.com/docs/en/hooks); [Claude Code monitoring](https://code.claude.com/docs/en/monitoring-usage)
- Cost figures are estimates and not bills, per Anthropic: "May differ from your actual bill" — [Claude Code status line](https://code.claude.com/docs/en/statusline)
- IDE agents hold usage server-side: "Cursor keeps no per-request token counts on disk" — [agent-walker docs/cursor.md](https://raw.githubusercontent.com/miiiiiiich/agent-walker/HEAD/docs/cursor.md)
- Anthropic's provider API cannot serve individuals: "The Admin API is unavailable for individual accounts." — [Anthropic Usage and Cost API](https://platform.claude.com/docs/en/build-with-claude/usage-cost-api)
- The private subscription-usage endpoint is rate-limited and unsupported (issue closed "not planned", 2026-06-01) — [claudeissues.com #31637](https://claudeissues.com/issue/31637-bug-api-oauth-usage-endpoint-aggressively-rate-limits-making-usage-monitoring-un)
- Credential reuse is restricted by terms: developers "may not collect, store, or intermediate Claude.ai credentials or session tokens" — [Claude Code legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- MCP config edits apply at restart in Claude Code; live changes need `list_changed` from a connected server — [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching); [Claude Code MCP](https://code.claude.com/docs/en/mcp)
- Slash commands cannot be injected into a running session ("A prompt that starts with `/` or `!` isn't sent") and the prompt cache is server-side — [Claude Code sessions](https://code.claude.com/docs/en/sessions); [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching)
- Hooks can block prompts and tool calls in Claude Code, Codex and Cursor — [Claude Code hooks](https://code.claude.com/docs/en/hooks); [Codex hooks](https://learn.chatgpt.com/docs/hooks); [Cursor hooks](https://cursor.com/docs/agent/hooks)

#### Architecture options, ranked by robustness
1. Vendor-sanctioned push/pull first: Claude Code status line, hooks and OTel; Codex `notify`, hooks, `[otel]` and `app-server`; Copilot/Cursor hooks; OpenCode's HTTP server. Most durable, but requires writing to users' settings and covers Claude Code far better than anything else.
2. Passive local-file watching with per-agent parsers and a LiteLLM-style price table. Broadest coverage with zero setup; inherits format churn and estimate-only accuracy. This is what every free competitor already does.
3. Polling undocumented vendor endpoints with reused credentials for subscription quotas and IDE usage. Necessary for Cursor/Copilot/Gemini quota display; highest breakage and terms risk; should be optional and clearly labelled.
4. In-path local proxy. Only route to hard enforcement and to exact per-request accounting for log-less BYOK agents; highest engineering and trust cost; should not be the default.

#### Overall technical reading
- Features (1), the estimated part of (2), and (4) are buildable by one developer in weeks, but they replicate free open-source tools.
- The differentiating promises in the pitch are the weakest technically: "instant" MCP context switching, "clear cached system context", provider-accurate unified spend for individuals, and team key deployment either do not map to real mechanisms or require the product to become a proxy/gateway/secret-custody service.
